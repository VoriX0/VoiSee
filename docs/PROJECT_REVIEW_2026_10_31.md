## Проекты и точки входа

| Проект / файлы | Назначение |
|---|---|
| `src/VoiSe.App` | WinUI 3, окна, вкладки, управление состоянием, хранение, темы, Windows-интеграция |
| `src/VoiSe.Audio` | WASAPI, DSP, микшер, транспорты звуков и Media Bridge, шумоподавление, AI-адаптер |
| `src/VoiSe.AudioHost` | Сохранённый отдельный хост аудиодвижка с JSON-командами через named pipe |
| `src/VoiSe.Gate0.Cli` | Консольный прототип и ручная диагностика аудио |
| `src/VoiSe.App/Program.cs`, `App.xaml.cs` | Запуск, единственный экземпляр, активация окна, фоновый запуск в трей |
| `src/VoiSe.App/MainWindow.xaml(.cs)` | Основной интерфейс и большая часть прикладной логики |

Стек: C#, .NET 8, Windows App SDK 1.6.*, NAudio 2.*, NAudio.Vorbis 1.*, YellowDogMan.RRNoise.NET 0.1.9. SDK в global.json — 9.0.315. Приложение unpackaged, win-x64, установщик Inno Setup 6. Собственного виртуального драйвера нет: используется VB-CABLE.

**Фактический основной путь:** MainWindow создаёт `Gate2UnifiedAudioEngine` напрямую. `AudioEngineClient`, `DetachedAudioHostLauncher`, отдельный AudioHost и альтернативный isolated output присутствуют в дереве, но их наличие не означает, что текущий UI работает через отдельный процесс. Это верно и для проверенного кода 12.5.1. Старые документы о process isolation нельзя использовать как описание действующего маршрута.

## Аудиотракт и обязательные инварианты

Текущий путь 13.x:

```text
Физический микрофон
  → преобразование в float32, 48 kHz, stereo (голос сводится в mono)
  → Off / RNNoise / DeepFilterNet
  → RVC AI Voice, если активен
  → упорядоченная цепочка обычных DSP-эффектов
  → очереди микрофона для двух выходов

VB-CABLE: микрофон + SoundBoard/сцены + Media Bridge → master gain → ограничение
Наушники: микрофон × voice monitor gain + SoundBoard/сцены → ограничение
```

В 12.5.1 отсутствует AI-ступень и последующая Fast/Full-инструментация серии 13.x.

- Голосовые эффекты и шумоподавление обрабатывают только микрофон. Звуки библиотеки и Media Bridge через них не проходят.
- Voice Monitor Off физически прекращает добавление голоса в очередь монитора и очищает её. Одного нулевого gain недостаточно.
- Media Bridge добавляется только в виртуальный микрофон: исходное приложение уже воспроизводит свой звук пользователю.
- Global virtual mic mute глушит весь виртуальный микс, сохраняя независимость мониторинга.
- SoundBoard имеет отдельные громкости и позиции чтения для виртуального выхода и наушников, а также отдельную задержку виртуального выхода; сохранённое значение по умолчанию — 85 мс.
- Сцены используют playback keys для управления отдельными звуками; библиотека и транспорты — разные уровни.
- Защита Discord периодически заглушает только его render sessions на обычном CABLE Input и восстанавливает изменённое состояние при штатном завершении.

В 13.0.1 запрошены буферы 10 мс capture / 20 мс render, очередь микрофона ограничена 250 мс, а пустая цепочка обходит обычный DSP. Телеметрия оценивает внутренние стадии; фактическую задержку от микрофона до получателя она не измеряет.

## Функциональная база 12.5.1

**SoundBoard:** импорт WAV/MP3/OGG, категории, поиск, переименование, горячие клавиши, перенос и копирование файлов между категориями, замена файла, открытие в Explorer, playback/pause/stop/seek/loop. PCM-кеш ускоряет повторный запуск звуков.

**Редактор звука:** waveform, выделение, trim outside, cut selection, gain/normalize/fade/distortion, предварительное прослушивание в наушниках, сохранение и Save as. Во время редактора обычные звуковые действия и горячие клавиши изолируются. Основная UI-логика редактора находится в MainWindow; обработка массива — в SoundEditProcessor.

**Voice Changer:** трёхколоночный Modular Rack: пресеты, вертикальная processing chain, библиотека эффектов. Добавление, перестановка, значения, bypass, preview, поиск и категории. В enum 34 типа эффектов: динамика, pitch/formant/EQ, модуляция, пространственные и характерные эффекты, включая восемь дополнений 12.5.0. Пресеты schema 2 сохраняют порядок и значения. Шумоподавление глобальное, вне пресета.

**Сцены:** выбор голоса, набор звуковых кнопок и один loop-фон либо Media Source, громкости и хоткеи. Активная сцена блокирует обычный transport SoundBoard. При отключении восстанавливается сохранённое состояние Voice Changer. Сцена не должна останавливать вручную запущенный Media Bridge, которым она не владеет.

**Media Bridge:** выбор окна, превью, process loopback с дочерними процессами, start/pause/resume/stop, два индикатора уровня, громкость виртуального микрофона и описательные профили. PID/HWND не сохраняются как постоянная привязка; автоподключение после перезапуска не выполняется. Код требует Windows build 20348+ для process capture, хотя базовый TargetPlatformMinVersion приложения — 19041.

**Система и оформление:** один экземпляр через mutex/named pipe, трей, автозапуск в HKCU, закрытие окна в трей, полный выход с освобождением ресурсов; native XAML ResourceDictionary темы с live reload, DPI PerMonitorV2 и нативная прокрутка. Старые CSS-темы архивируются и не загружаются. Исправление 12.5.1 пересоздаёт динамические карточки после смены темы, сохраняя данные.

## Хранение и совместимость

Основной каталог: `%LOCALAPPDATA%\VoiSe`.

| Данные | Формат / особенности |
|---|---|
| `settings.json` | Настройки устройств, микшера, хоткеев, темы, Media Bridge; текущая schema 13 |
| `soundboard.json`, управляемые звуковые файлы | Библиотека schema 2; звуки имеют стабильные ID |
| `presets/*.json` | VoicePreset schema 2: имя, иконка, Sliders, EffectOrder, хоткеи |
| `scenes/*.json` | Scene schema 9: кнопки, фон, голос, параметры микшера |
| `themes/*.voiseetheme.xaml` | Ресурсы WinUI; устаревшие CSS отдельно |
| `AI Voices/*.vsee` | Добавлено в 13.x: ZIP-контейнер manifest + reference/model/index/profile |
| `AI Runtime` | Отдельно устанавливаемая среда, модели инфраструктуры и кеш извлечённых голосов |

Повреждённые JSON пресетов/сцен пропускаются, ошибки настроек логируются с возвратом значений по умолчанию. Запись ряда JSON выполняется напрямую через File.WriteAllText, без общей схемы атомарной замены и резервного восстановления.

Есть существенная особенность сцен: сохраняется `VoiceSliders`, но отдельного `EffectOrder` в модели сцены нет. Если именованный пресет существует, применяется он с его текущим порядком; иначе fallback собирает цепочку по `KnownVoiceEffectKeys`. Поэтому сцена не является независимым точным снимком произвольного порядка DSP. Это статически подтверждённое ограничение, которое следует явно решить при развитии сцен.

## Что добавлено после рабочей версии

13.1–13.6 добавляют вкладку AI Voice, профили Gaming/Balanced/Quality, .vsee, локальную библиотеку, Hugging Face, подготовку reference, Quick и Optimize. Quick/Optimize здесь — подготовка аудио и метаданных; они не создают обученную нейросетевую RVC-модель.

13.7 подключает реальный RVC inference для .pth в отдельном Python-процессе. C# передаёт PCM через stdin/stdout; устройства остаются у основного движка. RVC source закреплён на commit `81eed5e8f68b6bed1789f682fe78cdd324495afc`; установка отделена от базового установщика. Есть проверка checkpoint через weights_only, кеш по revision, диагностика очередей/underrun и rollback ремонта среды.

Профили используют блоки 80/120/200 мс. Это параметры обработки, а не гарантии полной задержки. При ошибке активного AI-пути код выдаёт тишину вместо скрытого перехода на исходный голос. FAISS retrieval отключён (`index_rate=0`). Reference/Quick/Optimized без обученного RVC не активируются этим backend; ONNX-only также не является рабочим RVC-путём. Zero-shot backend, сохранение AI-голоса в сцене и автоматическое соблюдение потолка Gaming ещё не реализованы.

## Технические точки внимания для следующего ТЗ

1. **Основание разработки.** Явно выбрать исходники 12.5.1 либо продолжение 13.x. Считать 13.x подтверждённо рабочей заменой 12.5.1 оснований пока нет.
2. **Связанность UI.** MainWindow.xaml.cs содержит 13 680 строк, XAML — 1902. В одном классе смешаны редактор, сцены, хоткеи, хранение, управление движком, темы и AI. Это увеличивает область регрессий; выделение компонентов следует привязывать к конкретной следующей функции.
3. **Сцены и пресеты.** Для точного снимка цепочки нужны порядок, стабильная идентификация пресета и определённое поведение при его изменении/удалении; сейчас связь голосового пресета идёт по имени.
4. **Аудио и память.** Полностью декодированные звуки кешируются в памяти; явного ограничения размера кеша нет. Преобразование микрофонных блоков создаёт массивы, а DSP содержит состояние задержек/модуляции. При оптимизации нужны измерения allocations, очередей и underrun.
5. **Сохранность данных.** При изменении схем следует предусмотреть миграции, атомарную запись и восстановление, особенно если планируется возврат между 12.x и 13.x.
6. **Воспроизводимость поставки.** Версия продублирована в нескольких файлах; часть NuGet-версий задана wildcard. README, ROADMAP и отдельные комментарии устарели. Сохранённые альтернативные аудиохосты следует явно обозначить.
7. **Проверки.** В отслеживаемом дереве не обнаружены отдельные проекты автотестов и CI-конфигурации. Smoke-документы часто описывают статический анализ, а не состоявшийся Windows audio test. `smoke-installed.ps1` запускает приложение и предлагает ручную проверку.
