# VoiSee 14.1.1 — память и основы устойчивости

Первая итерация ветки `14`, основанная на рабочей 12.5.1 (`b1829bb`). AI-функции экспериментальной 13.x не переносились. Спецификация серии: [SPEC_14_DRAFT.md](SPEC_14_DRAFT.md).

## Изменения

- Кеш коротких звуков ограничен 64 МиБ, вытеснение — LRU. Полная библиотека больше не декодируется при запуске движка или восстановлении настроек.
- Короткие файлы до 8 МиБ декодированного PCM используют кеш. Более длинные проигрываются фоновыми декодерами с read-ahead 250 мс на каждый подключённый выход; операции чтения файлов и ресемплинг не выполняются внутри WASAPI Read.
- Микшер повторно использует scratch-буфер вместо создания массива для каждого звука при каждом чтении. В steady-state тесте восьми коротких звуков и двух выходов получено **0 managed allocations на блок**.
- Аудиоочереди заменены фиксированными кольцевыми буферами. Звук корректно завершается при отсутствии выхода мониторинга; сохранены независимые громкости и задержка виртуального выхода.
- Добавлены защита от запоздалого завершения Play после Stop/Dispose и ограничение до 32 overlay-звуков. Превышение явно сообщает ошибку, не отключая работающие эффекты.
- Полное декодирование для редактора использует предвыделенный массив вместо List + ToArray; слишком большие материалы отклоняются с ошибкой до исчерпания памяти. Текущий предел — 128 МиБ PCM, не размер сжатого файла. Обычное воспроизведение длинных файлов остаётся потоковым.
- Refresh получает новые снимки capture/render endpoint через свежие enumerator-объекты. Доступный выбор сохраняется по ID; исчезнувший выбранный микрофон снимается с выбора. Изменившиеся маршруты работающего движка останавливаются/пересоздаются согласованно с UI.
- Поиск устройств включён в транзакцию запуска. Ошибки capture/render передаются UI, а закрытие каждой части движка выполняется независимо от ошибок других частей. Указано владение endpoint-объектами.
- Pending Media Bridge не может активироваться после Stop/Dispose. Native capture worker освобождает свои COM-ресурсы после завершения, а не из другого потока после истечения Join timeout.
- Настройки, библиотека, пресеты и сцены используют общую атомарную запись с `.bak`. Повреждённый JSON сохраняется отдельно; при наличии корректного backup он восстанавливается. Ошибки сохранения не скрываются в успешных UI-действиях.
- Замена трека сначала полностью копирует новый файл, затем обновляет библиотеку и только после успешного сохранения удаляет старый. Исправлена воспроизводимая потеря исходного файла при заблокированном source.
- RNNoise не создаёт native denoiser, пока он выключен. Невидимые timeline/meters не обновляются постоянно; история UI-лога ограничена, startup log ротируется. На закрытии явно останавливаются оставшиеся таймеры.
- Версия обновлена до 14.1.1 во всех действующих источниках версии. Установщики/portable размещаются в каталоге версии, чтобы следующая сборка не удаляла старые установщики.

## Проверка

Release build/publish Windows x64, отдельный регрессионный стенд без внешнего test framework, сборка Inno Setup. Подробности и ручная матрица: [SMOKE_REPORT_14_1_1.md](SMOKE_REPORT_14_1_1.md).

Это основы оптимизации, а не заявление об устранении всех возможных вылетов. Физическое подключение/отключение USB/Bluetooth и воспроизведение через микрофон/Discord требуют ручного прогона. WASAPI latency targets и DSP-математика 12.5.1 в этой итерации сохранены; отдельный этап снижения задержки, вкладка EQ 10/31, жест удаления, локализация и сокращение полного runtime-пакета следуют далее.

Выделены самостоятельные компоненты PcmCache, ReadAheadSound и AtomicFile. Полный перенос UI на ViewModels и процессная изоляция движка не выполнялись одним большим изменением.
