# VoiSee: согласованный процесс разработки

## Ветки, версии и коммиты

- Для каждой крупной серии обновлений создавать отдельную Git-ветку с номером серии: например, `14`. Это выбранное пользователем имя; не заменять его на `codex/14`.
- Все обновления одной серии выполнять в этой ветке. Для отдельных исправлений и подэтапов новые ветки не создавать.
- Версия имеет вид `серия.этап.итерация`. Пример: `14.1.1` — первый этап оптимизации; `14.1.2` — исправление сборки; `14.1.3` — доработка того же этапа; `14.2.1` — начало следующего этапа, например исправления вылетов.
- Каждый отдельный пользовательский запрос на изменение приложения оформлять отдельной версией и отдельным коммитом. Связанные исправления и проверки внутри выполнения одного запроса входят в его коммит; не увеличивать версию за каждую внутреннюю попытку инструмента.
- Обсуждение, анализ, вопросы и согласование процесса сами по себе не требуют новой версии приложения или коммита.
- Если пользователь назвал версию, использовать её. Иначе для продолжения текущего этапа увеличивать итерацию; при переходе к новому этапу увеличивать этап и начинать итерацию с 1.
- Версию согласованно обновлять во всех действующих источниках версии приложения и поставки. Коммит должен обозначать версию и конкретное изменение.
- Перед коммитом выполнять относящиеся к изменению сборку/проверки. В отчёте честно указывать результат, включая неустранённые ошибки и ограничения проверки.
- Не включать в коммит посторонние пользовательские изменения или весь набор untracked-файлов автоматически.
- Сливать серию в `main` после подтверждения пользователем, что работа над серией завершена. Успешная сборка или одобрение отдельного промежуточного этапа сами по себе не являются разрешением на merge.
- Не выполнять push без запроса пользователя или ранее данного разрешения.

## Исходная база оптимизации

- Пользователь определил 12.5.1 последней рабочей версией. Для первой серии архитектуры/оптимизации согласована база поставки `b1829bb` (исходники релиза — `685bea1`).
- Текущая main содержит более позднюю экспериментальную серию 13.x. Не переносить её AI-функциональность в оптимизацию автоматически и не сбрасывать main к 12.5.1.
- Перед итоговым merge ветки на базе 12.5.1 явно проверить расхождения с main: обычный merge может сохранить изменения 13.x. Состав итогового продукта должен соответствовать согласованному пользователем объёму.
- Пользователь разрешил начать первый этап в ветке `14` с версии `14.1.1`: память, безопасное хранение, lifecycle и Refresh устройств. Эквалайзер, жесты, локализация и отдельный этап уменьшения задержки следуют по ТЗ. Дальнейшие версии назначаются по запросам пользователя.
